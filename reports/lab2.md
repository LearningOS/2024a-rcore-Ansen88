## 简单总结你实现的功能

本章作业主要实现了两个功能：
+ mmap()
+ munmap()

改写了两个系统调研：
+ 获取当前时间
+ 获取当前任务的信息

由于本章使用了MMU，所以使用了页表来做虚拟地址和物理地址的映射，且内核地址和用户空间的地址是分开的。当我们需要内核空间和用户空间相互传递数据时，需要将用户空间的物理地址映射到内核空间，然后再在内核空间进行相应的操作。在sys_get_time 和 sys_task_info两个系统调用中，将用户空间先映射到内核空间，然后在将在内核中获取到的数据拷贝到内核空间。

mmap 主要实现了：给要映射的虚拟地址分配页表和物理地址，建立相应的映射关系，并将该映射关系保存在一个btree中；

munmap 主要实现了：获取到要操作的虚拟地址的映射关系，将其从btree中删除，并解除虚拟地址和物理地址的映射关系；



## 问答作业

***第一题***

请列举 SV39 页表页表项的组成，描述其中的标志位有何作用

SV39 分页机制被启用，所有 S/U 特权级的访存被视为一个 39 位的虚拟地址，MMU 会将其转换成 56 位的物理地址；如果转换失败，则会触发异常。

SV39 分页模式下的页表项，其中 [53:10] 这 44 位是物理页号，最低的 8 位 [7:0] 则是标志位，它们的含义如下：

- 仅当 V(Valid) 位为 1 时，页表项才是合法的；
- R/W/X 分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指；
- U 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问；
- G 我们不理会；
- A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过；
- D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过。



***第二题***

1. 请问哪些异常可能是缺页导致的？
   + 虚拟地址还未分配物理空间；
   + 访问无效的地址空间
2. 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。
   + PC : 保存发生异常指令的地址。
   + badaddr 寄存器得到产生异常的虚拟地址
   + cause 寄存器存有页异常原因有关信息
   + satp : 包含页表的基址和一些控制位，用于地址转换。
3. Lazy 策略这样做有哪些好处？
   + 在实际使用时才进行内存分配操作，减少了初始化时的加载时间；
   + 避免了不必要的I/O操作，提高了系统整体性能；
4. 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？
   + pte0: 10G / 4k = 2621440
   + pte1: 2621440 / 512（9 bits） =  5120
   + pte2: 5120 / 512 (9 bits) = 10
   + 大概需要的字节数：2621440 + 5120 + 10 = 2626570 ，大概 2.5 M 字节
5. 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现
   + 在虚拟地址空间中获取对应的地址空间和空间长度
   + 在第一次写入数据的时候再建立页表和分配物理空间
6. swap策略导致应页面失效，此时页面失效如何表现在页表项(PTE)上？
   + 有效位(`V`): 如果页面被换出到磁盘，页表项的有效位会被清除。
   + 使用`RSW`位来存储额外的状态信息，可以区分真正的无效的页表项和被换到磁盘上的页表项的位置
